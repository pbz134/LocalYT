Documentation

Comprehensive guide and wiki for LocalYT

Hardware Requirements

LocalYT should be able to run on almost any Windows computer, but specific tasks like generation of subtitles, tags and seek bar previews require more powerful hardware to be fast.

Minimum Hardware requirements:

  • CPU: Any CPU that supports AVX1 instructions (AVX2-compatible CPU recommended).
  • GPU: No dedicated GPU is needed, but would significantly speed up some metadata generation.
  • RAM: At least 12 GB system memory.
  • Required Storage: 3 GB for the LocalYT application and its dependencies, 500 MB for full metadata of 1000 videos (example).
  • Non-mandatory storage: 5 GB for all Whisper (subtitle generation) models, 20 MB for yt-dlp (metadata fetching).
  • Storage type: HDD or SSD (Micro SD or USB Flash Drive NOT recommended).
  • Network: Only required for initial Fluid Player asset download and remote access

Software Requirements

To run LocalYT, the following software is required.

  • OS: Windows 10 or 11
  • Node.js: Version 20.x or higher (Latest version recommended).
  • FFmpeg: Any FFmpeg version that supports AV1 codec and image file handling (must be added to PATH).
  • Python: Integrated in the portable GitHub release, version 3.10 or higher.
  • Browser: Any modern browser for accessing the web UI.

Installation

Setting up LocalYT involves downloading one of the GitHub releases and preparing it for launch.

Step 1: Download the latest release
Download LocalYT-vXX.7z and decompress it into your desired directory (e.g., D:\LocalYT).

Step 2: Prepare videos
Download any H.264. VP9 or AV1 codec videos or .mp3 audio files and paste them into /videos/[channelname].

Channel playlists are supported as well. Use them by creating subfolders within channel folders.

Example:

/videos/Modern Vintage Gamer/Xbox Guide.mp4 or /videos/S3RL/best songs of 2020/Cool Music.mp3

Step 3: Add metadata
If you already have metadata, you can insert them into their respective metadata directories. Each channel requires its own folder in all directories.

Example:

/thumbnails/Domtendo/Mario Bros. Playthrough.jpg or /viewcounts/Goose's Gamer Folklore/Goldeneye Speedrun.txt

If you don't have metadata available, you can fetch them like so:

1. Run LocalYT-Debug/get-latest-ytdlp.bat to download the latest yt-dlp version.

2. Run LocalYT-Debug/download-channel-or-playlist.bat to get your desired video links into a .txt file.

3. Run LocalYT-Debug/Fetch-GUI.bat to fetch all required video metadata.

Step 4: Run the Server
Double-click #Setup-or-Update.bat and let the script finish organizing and generating all the necessary metadata.

Note that this can take a while, depending on your amount of video and audio files, and your CPU/GPU power.

Once the server is ready, your browser should open http://localhost:3000 automatically.

For full offline access with other computers, connect an Ethernet cable to your LocalYT server and guest computer

Then, visit http://[IPV4 of server]:3000 in your browser.

For remote access, consider using a cloudflared.exe tunnel, a VPN, or port-forwarding.

Caching

LocalYT utilizes caching mechanisms to manage massive video databases, even on slow drives.

  • video_cache.json: References all video and audio file paths for fast page loading.
  • recommendation_index.json: References all video and audio file paths for instant recommendation/algorithm adjustments.
  • shortlinks.json: Stores shortened video links, e.g. http://localyt.net:3000/v/7bWeLpJ.

    • Compatibility

    LocalYT supports several media formats and codecs.

    • Video Formats: MP4 and MKV (H.264, VP9, AV1 codec)
    • Audio Formats: MP3
    • Metadata Formats: TXT, JSON, JPG, SRT, VTT

    Troubleshooting

    Encountering issues? Here are solutions to common problems.

    Problem: Videos won't play.
    Solution: Ensure the file path in your configuration does not contain special characters that break URLs. Check that the format is MP4/WebM. Check the browser console (F12) for CORS errors.

    Problem: Server won't start (Port in use).
    Solution: Another application might be using port 3000. You can change the port in server.js or kill the process using that port.

    Problem: Metadata is missing.
    Solution: Run the metadata gathering script manually via Python to ensure there are no errors in the console output. Check that your .json files are not malformed.

    User Management

    LocalYT includes a basic authentication system to allow multiple users to maintain separate profiles on the same machine.

    The system handles registration, login sessions, and profile persistence. User data is stored locally in JSON files, meaning there is no cloud dependency. The "Admin" user typically has elevated privileges to trigger global metadata updates or manage users.

    Metadata Backup

    Your metadata is the backbone of the library organization. It is crucial to back this up regularly.

    All metadata is stored in structured JSON files within the data or metadata directory. To backup, simply copy this entire folder to an external drive or cloud storage. In the event of a system failure, restoring these files will instantly bring back your watch history, likes, and video descriptions without needing to re-analyze the video files.

    Metadata Gathering

    How does LocalYT know what your video files are? It uses a gathering process.

    Python scripts scan your designated video directories. For each file found, it attempts to extract metadata such as title, duration, resolution, and codec information. If configured, it can also use Speech-to-Text (STT) models to transcribe audio, which is then used for search indexing and description generation.

    Metadata Integration

    Once gathered, raw data must be integrated into the frontend.

    The Node.js backend reads the generated JSON files and serves them via API endpoints (e.g., /api/videos). When you load the homepage, JavaScript fetches this data and dynamically generates the HTML cards you see. This separation allows the UI to remain fast while the heavy lifting is done by the backend.

    Algorithm

    The "Algorithm" in LocalYT determines what videos appear in your recommendations and search results.

    Unlike commercial platforms that track you for ads, LocalYT's algorithm is based purely on content similarity and your local interaction history. It uses vector embeddings or tag matching (generated via the Qwen model) to find relationships between videos. If you watch a video about "Cooking", the algorithm checks other videos for "Cooking" tags or similar transcription keywords to suggest them next.

    Name

    The user's display name. This is shown in the top bar next to the profile picture and on the settings page. It can be changed at any time without affecting login credentials.

    Password

    User passwords are hashed before storage. We do not store plain-text passwords. If you forget your password, the current workflow involves resetting the entry in the users.json file or using a recovery script provided in the tools directory.

    Profile Image

    Users can upload a custom avatar. Images are resized and saved to the assets folder. Default avatars are used if no custom image is uploaded. Supported formats include JPG, PNG, and GIF.

    Preferences

    This includes UI settings such as theme variations (if applicable), default video quality selection, and autoplay toggles. Preferences are stored per-user in the session data.

    Login Attempts

    For security, the system tracks failed login attempts. After a threshold (e.g., 5 failed attempts), the account may be temporarily locked out or throttled to prevent brute-force attacks, even on a local network.

    Search History

    A list of recent search queries performed by the user. This is useful for quickly re-finding content. It is stored locally in the user's data object and cleared when history is wiped.

    Watch History

    A chronological log of every video played. This data powers the "Watch History" page and contributes to the recommendation algorithm. It records the Video ID, Timestamp of viewing, and Watch duration (progress).

    Liked Videos

    A collection of Video IDs that the user has explicitly "Liked". This acts as a favorites list. These videos are accessible via the liked_videos.html page.

    users.json

    This is the core database file for user accounts. It contains objects for each user, holding their ID, hashed password, name, and paths to their profile images. Manual editing of this file should be done with caution to maintain valid JSON syntax.

    about.html

    The static informational page for the project. It contains credits, technology stack info, and a brief overview of what LocalYT is. It uses the standard layout but focuses on text content rather than dynamic data.

    channel.html

    In LocalYT, a "Channel" usually represents a folder or a creator tag associated with multiple videos. This page displays a banner image (if available), channel statistics (total videos, total views), and a grid of all videos belonging to that specific channel entity.

    genre_channel.html

    Similar to the channel page, but filtered by Genre tags (e.g., "Gaming", "Music", "Education"). It aggregates videos across different folders that share the same genre metadata tag.

    index.html

    The homepage and landing pad of the application. It features the main feed of videos. Depending on the user's state, this might show "Recommended" videos, "Recently Added", or "Continue Watching". It is the central hub for navigation.

    liked_videos.html

    A personal playlist of videos the user has clicked "Like" on. It allows users to quickly access their favorite content without creating a manual playlist.

    login.html

    The authentication gateway. It provides fields for username and password. Upon successful validation against users.json, a session token is created, and the user is redirected to the index.

    playlist.html

    The view for a specific user-created playlist. It lists the videos in the order set by the user and includes controls to reorder or remove items from the list.

    register.html

    The interface for new users to create an account. It validates username uniqueness and password strength before writing the new entry to the user database.

    search.html

    Dedicated to displaying results for a query string passed via URL parameters (?q=searchterm). It searches through titles, descriptions, and auto-generated tags. Results are ranked by relevance.

    settings.html

    Allows users to configure their account. Options include changing the display name, uploading a new profile picture, changing the password, and managing data export/deletion.

    shared_playlist.html

    A view-only mode for playlists. If a user generates a share link for a playlist, other users (or guests) can view this page to see the list of videos without having editing permissions.

    subscribed_channels.html

    Displays a grid of channels/folders that the user has chosen to "Subscribe" to. Subscribing ensures that content from these sources appears more prominently in the home feed.

    user_playlists.html

    The management hub for all playlists created by the logged-in user. From here, users can create new playlists, delete old ones, or edit details (title, privacy setting).

    video.html

    The core viewing experience. This page hosts the Fluid Player instance, the video title, description, and metadata. It also features the sidebar with "Up Next" suggestions. It handles the logic for updating watch history and progress tracking as the video plays.

    watch_history.html

    A chronological list of watched videos. Each item shows a thumbnail, title, and how long ago it was viewed. Users can clear this history or resume playback from where they left off.

    Python venv

    We use Python Virtual Environments (venvs) to isolate our dependencies. This prevents conflicts between LocalYT's required libraries (like OpenAI Whisper, Transformers) and other Python projects you might have on your system. Always ensure your venv is activated before running metadata scripts.

    Fluid Player

    Fluid Player is the open-source HTML5 video player used by LocalYT. It was chosen for its lightweight nature, lack of tracking, and customization options. It handles the actual playback of MP4/WebM files inside the browser, providing controls for play/pause, volume, fullscreen, and theater mode.

    Limitations

    Please be aware of the following limitations:

    • No Streaming: This is a local library. You cannot stream content *to* the internet easily without additional networking setup (Nginx reverse proxy, port forwarding).
    • Mobile Support: While responsive, the UI is primarily optimized for desktop use (mouse/keyboard).
    • AI Accuracy: Auto-generated tags rely on local LLMs. They are generally good but can sometimes produce hallucinations or irrelevant tags depending on the model size.
